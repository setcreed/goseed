# 实施方案

## 执行原则

按依赖顺序交付可验证结果，先文档与技术核验，再模板，再项目生成器，再业务生成器。首版能力范围由需求文档确定，分检查点完成不代表移除可选能力。

执行范围与完成状态统一以 ROADMAP 为准，后续检查点按用户指令推进。本文件是开发计划，不是已经启动的 Goal；检查点描述验收范围，可独立验收的功能按项目规范分别提交。

正式开发前检查工作区，不覆盖用户改动；需求或接口发生变化时先更新对应规范文档。验证通过后才能将检查点移入 ROADMAP 的最近完成。

## 检查点 D0：文档基线

交付项目规范、需求、架构、命令契约、实施方案、README、ROADMAP 与 `.gitignore`，初始化 `main` 分支。

验证内部链接、默认值和能力组合一致；README 不把规划写成已实现功能；配置模板可跟踪，真实配置、数据库及本地产物被忽略；不出现参考项目名称。功能完成后的 Git 提交流程统一遵循 AGENTS 中的项目规范。

## 检查点 D1：技术核验与工程入口

核验 Go 版本、核心依赖维护状态、兼容性和许可证，记录官方来源、发布/提交/issue 的实际证据与固定版本。明确 SQLite 驱动、Casbin 策略适配器、协议工具及文档输出版本。

验证 SQLite 驱动的目标平台构建、Context、PRAGMA、事务、锁等待和错误识别；验证 Casbin 适配器关闭自动建表和三种数据库策略加载。不能通过隐含引入第二套 SQLite 驱动解决兼容问题。

建立 Go 模块、最小 CLI、测试与格式检查入口。主模块为 `github.com/setcreed/goseed`，工具链固定为 Go 1.26.4。工具锁定在项目范围，普通构建不修改源码或依赖。许可证尚未确定，公开发布前确认；不阻塞本地设计与验证。

预期失败：依赖下载失败、驱动构建失败、适配器隐式 schema 变更、工具版本不匹配，都有明确记录及解决方案后才继续相关实现。

## 检查点 D2：默认模板

交付 HTTP + 文件 SQLite + JWT + `example` CRUD 完整模板，以及配置、日志、错误、Context、迁移和生命周期。

先实现普通构造函数，再通过 Bootstrap 使用 do 组装；生成项目无运行时 goseed 依赖。开发初始化与测试 Token 的明确使用路径形成文档，不公开无验证签发接口。

验收包括：启动、迁移、认证后 CRUD、分页边界、更新零值与缺失值、非法请求、唯一冲突、跨仓储事务回滚、无效与过期 Token、配置覆盖、启动失败清理、取消和限时关闭。

持久化验证需重启后读取已保存数据，并验证文件与日志没有泄露密钥。没有完成备份恢复和容量评估时，仅声明已验证的基础能力。

## 检查点 D3：数据库、缓存与授权变体

交付 MySQL、PostgreSQL、无数据库、Redis 和 Casbin 模板能力。每个变体同步裁剪源码、运行依赖、配置、迁移、文档和测试。

MySQL、PostgreSQL 使用真实服务验证迁移、CRUD、约束错误、事务回滚、Context 与连接管理。无数据库项目能编译与运行，且不含 ORM、迁移或隐藏内存 Store。

Casbin 验证三种数据库策略存储和无数据库只读文件策略，覆盖默认拒绝、权限允许、权限拒绝及资源归属；确认无未经授权的策略管理入口。

Redis 验证命中、失效、回源、超时、连接故障、必需状态失败及关闭。开启 Redis 不改变 JWT/Casbin 存储方案。

## 检查点 D4：gRPC、dual 与 Gateway

交付 Proto、生成代码、RPC Handler、拦截器、标准健康服务、TLS、可控 Reflection 和示例客户端；实现 dual 与 Gateway 的服务生命周期。

验收身份上下文、JWT/Casbin、共享校验、错误映射、请求 ID、deadline、取消、请求限制与恢复。四种协议分别运行，dual/Gateway 对照同一业务输入输出。

验证 Gateway 转发 Authorization 和请求 ID、启动中途失败清理、HTTP 请求排空后关闭 gRPC、gRPC 优雅关闭超时兜底，以及证书错误确实被拒绝。

普通构建不要求重新编译 Proto；契约修改后的生成可复现。首版不提供流式业务生成，禁止留下未经安全链保护的流式入口。

## 检查点 D5：项目生成器

将已验证模板嵌入生成器，交付根命令、全部参数、元数据及 dry-run。初始化命令只生成，不执行 Git、迁移、全局安装、容器启动或部署。

验收空目录默认生成、真实模块路径、所有合法能力组合的生成与编译，以及代表组合运行。非法枚举、非法名称、非空目录、冲突、符号链接越界、渲染失败和写入失败均有验证。

元数据包含固定模板版本；生成过程不需要查询最新模板。依赖下载与外部服务访问发生在明确的构建/运行阶段，不以隐式网络行为补齐生成错误。

## 检查点 D6：业务生成器

命令、字段声明、文件归属和登记规则已在 [命令契约](cli.md#生成业务模块) 定义。`internal/openapi.Merge` 已实现多份 Swagger 2.0 YAML 的确定性合并、重复定义/操作冲突检查、规范化 JSON 和 SHA-256；HTTP、dual 与 Gateway 项目会把内置 Swagger 同时保存为 `example.yaml` 源文件和规范化索引。`generator.LoadProject` 严格读取版本化元数据及登记源文件，校验现有索引的 SHA-256，并计算当前源文件的合并结果以标记待更新状态；`PrepareOpenAPIRefresh` 生成只读可审阅计划，并在执行前复核源文件和目标字节，原子替换 Swagger 索引及摘要，后续替换失败时恢复已更新文件。新项目清单使用带名称和类型的结构化模块项，旧版字符串项按普通模块兼容读取；资源项校验 `specs/` 路径与字段规范版本。四种协议登记索引按清单确定性渲染并带模块摘要。`generator.PrepareModule` 与 `goseed gen module` 已接入行为骨架生成、协议登记、OpenAPI 更新和 dry-run；计划执行前重验所有输入与目标，创建新源码后更新登记文件，后续失败回滚本次创建和此前更新。骨架不伪造业务操作，纯 gRPC 项目不生成 HTTP OpenAPI。D6 资源阶段按顺序交付严格 spec 解析、资源生成计划、四协议 CRUD、显式迁移草稿和主体隔离验证。

交付协议适配骨架、主体隔离 CRUD、显式迁移草稿、字段校验、测试、元数据登记与冲突保护。新业务文件由开发者维护；`goseed.yaml`、`modules_gen.go` 与聚合的 `api/openapi/swagger.json` 是可再生成登记/汇总文件，带摘要/标记并在更新前校验改动。

验收新模块注册后可编译与调用；HTTP、gRPC、dual、Gateway 共享相同 Biz；CRUD 执行显式迁移后可运行。覆盖重复名称、字段/类型/约束非法、保留字段、重复 YAML 键、名称碰撞、路径越界、dry-run、工具缺失、冲突、登记文件手工修改及多文件写入失败；任何准备阶段失败不写入，提交阶段失败只回滚本次创建/更新内容。

资源字段解析、模块工厂和固定启动组装入口已交付，可作为资源 CRUD 的前置基础。实际验证范围及当前状态见 [ROADMAP](../ROADMAP.md) ，后续资源接入按下面的施工清单执行。

### D6 剩余施工清单

本清单定义任务范围、依赖与验收门槛，不另行维护进度；任务当前状态、完成记录和验证结果只写入 ROADMAP。R01 定稿的接口与技术决策见 [资源接入方案](resource-generation.md) 。每个任务按「规范定稿 → 实现 → 必要验证 → 文档同步 → 本地提交」交付，每次验证后立即清理本次产物；同一任务中的独立功能通过验收后即可提交，不等待全部 D6 完成。

#### 目标与共同边界

- 最终交付 `goseed gen resource <name> --spec specs/<name>.yaml [--dry-run] [--migration]`，支持 HTTP、gRPC、dual、Gateway 与 SQLite、MySQL、PostgreSQL；无数据库项目在写入前拒绝资源生成，继续使用 `gen module`。
- 保持 Handler → Biz → Store 分层、显式构造、单次模块组装和共享连接池；Biz 不接收 DI 容器、GORM 或启动依赖结构，dual 两种 Handler 复用同一 Biz。
- 首版字段、输入、权限和文件归属严格遵循 [命令契约](cli.md#生成-crud-资源) 与 [架构约定](architecture.md) ，不扩展复杂业务规则、关系、索引 DSL、缓存框架或公开策略管理接口。
- 优先标准库与已有依赖，不新增同类 ORM、DI、配置或日志库。确需新增依赖时，先核验官方维护情况、许可证和 Go 1.26.4 兼容性，再更新依赖文档及锁定清单。
- 生成过程不连接数据库，不执行迁移、Git、网络下载、容器启动或隐式 tidy；协议工具必须在项目内显式准备。普通业务项目构建使用已生成 Proto 代码。
- spec、现有业务源码、既有工厂、Proto 源和已存在迁移均作为受保护输入；所有冲突、输入变化和工具失败尽可能在写入前拒绝。多文件提交失败恢复本次变更，不能保证恢复时必须列出残留对象，不宣称跨文件天然原子。

文件归属验收表：

| 对象 | 新资源生成行为 | 后续增加其他资源的行为 |
|---|---|---|
| Model、Biz、Store、Handler、模块工厂、测试、模块文档 | 创建新文件，开发者维护 | 不改写既有文件 |
| `specs/<name>.yaml` | 读取用户提供的规范 | 不改写、不自动升级 |
| `api/proto/<name>/v1/`、模块 OpenAPI 源 | 按所选协议创建 | 不覆盖旧模块手工源文件 |
| `pkg/api/<name>/v1/` | 用固定工具生成新模块协议代码 | 新资源命令不重新生成旧模块代码；显式协议复现另按声明范围执行 |
| `migrations/` 下当前方言 SQL | 仅 `--migration` 创建新草稿 | 不改写已存在 SQL，不自动应用 |
| `goseed.yaml`、`internal/apiserver/bootstrap/modules_gen.go` | 校验后更新清单和登记投影 | 校验后确定性更新 |
| `api/openapi/swagger.json` | HTTP、dual、Gateway 校验后汇总；纯 gRPC 裁剪 | 校验后更新汇总，不丢弃旧模块 |
| `providers.go`、运行配置、依赖文件及通用工具脚本 | 资源命令不修改 | 不为增加资源重写这些文件 |

通用模板入口可以在本仓库的对应施工任务中升级；已生成项目的增量命令不能借此静默升级旧模板。新入口不兼容时明确拒绝，并给出需要人工更新的对象。

#### D6-R01：定稿接入接口和前置技术决策

**目标与入口**：对照 `internal/generator/resource_spec.go`、`module_plan.go`、`module_assembly.go`、`internal/templates/module.go` 及四协议模板，定稿 ResourcePlan 输入/输出、渲染入口、模块工厂返回值和权限/迁移/协议工具接入方式。先更新受影响的需求、架构与命令契约，不开始编写 CRUD。

**施工项**：

- 固定每种协议/数据库的文件计划、命名转换、CRUD 操作与权限映射；确定 DTO/模型转换、分页上限、排序、ID 与时间响应格式，复用已有示例约定，不凭渲染器各自推断。
- 定稿 Casbin 可验证的资源/操作目录及其显式传入接口。启动和离线策略命令必须共用目录；获取目录不能启动服务、连接 Redis 或构造完整业务依赖，不能读取运行时 `goseed.yaml`。
- 定稿迁移期望版本与资源 schema 缺失的失败行为。优先从嵌入迁移文件校验并推导版本，避免每加一个资源重写固定 `migrations.go` 或增加第四个登记索引；明确不带 `--migration` 时的人工建表与核验路径。
- 定稿多模块协议生成的输入发现、导入路径与输出范围，以及 Gateway 模块文档和汇总摘要如何保持一致。生成新资源与显式重新生成已有协议是两个不同入口，保护范围分别说明。
- 定稿新资源的 Redis 行为。优先首版 CRUD 直接访问数据库，不自动增加缓存；仍须保持所选 Redis 的可选回源、必需模式、就绪和关闭契约，不能因新资源绕过必需依赖失败语义。
- 明确旧模板兼容检查；不能支持的旧入口报错，不自动修改手工 Bootstrap、策略代码或协议脚本。确有契约变化时同步版本规则。

**关键失败路径**：权限目录依赖业务初始化、schema 期望值与实际迁移冲突、Proto 同名导入碰撞、旧模板无法安全增量接入，均须先形成明确结论，不把未决架构问题交给实现阶段猜测。

**验收与交付**：交付接口/决策表、正反例及后续测试对象；执行 `make contract-check`、`git diff --check`，人工核对文件归属与四协议裁剪。独立 `docs:` 提交，ROADMAP 指向下一任务。

#### D6-R02：只读资源生成计划及预览

**目标与范围**：在 `internal/generator/` 按需新增资源计划实现，复用现有项目加载、spec 解析、冲突保护和 OpenAPI 合并；先交付内部准备/预览能力，不暴露未完整实现的公共命令。

**施工项**：

- 加载项目能力、清单、spec、启动入口和既有工厂；校验资源/模块共享命名空间、保留名称、存储支持及 spec 位于受允许的 `specs/` 路径。
- 生成稳定的新增/更新文件清单、摘要、可审阅差异、当前方言迁移需求与固定协议工具需求；预览与最终执行使用同一份计划。
- 记录所有影响输出和冲突判断的输入快照，包括 spec、既有登记/文档源、工厂、启动入口以及迁移目录状态；计划执行前重新验证。
- 检查目标父目录、路径越界、符号链接、同名目录/文件、已有资源文件及生成登记被手工修改。Go 导出名和协议名称碰撞在写入前拒绝。

**关键失败路径**：无数据库、重复名称、非法 spec、文件冲突、工具缺失/错版、手工改写索引、准备后修改输入或新增同号迁移；准备阶段保持原树不变。

**验收与交付**：定向生成器测试核对计划确定性、错误对象和树快照；含四协议/三数据库计划及无数据库拒绝。受影响包 test/vet、契约与 diff 检查通过后，以 `feat:` 提交计划能力；最终渲染和写入在后续任务补齐。

#### D6-R03：Casbin 模块权限目录

**目标与范围**：升级 Casbin 模板的策略校验、构造/加载/导入入口与必要启动登记。当前 `variants/casbin/common/internal/pkg/authz/policy.go.tmpl` 的权限校验只接受 `example`，必须通过显式目录接入真实资源。

**施工项**：

- 按 R01 的接口共享资源/操作描述，资源 CRUD 使用已约定的 `create/read/update/delete`；普通模块保留手工权限声明能力，不能仅放宽名称正则接受任意资源。
- 启动、文件读取、SQL 加载、导入、替换和 Reload 都使用同一校验来源；Context 显式传递，失败不发布部分策略快照。
- 保持默认拒绝、`user:`/`role:` 独立命名空间、精确 FullMethod 和 JWT → Casbin → Biz/缓存顺序；授权成功仍不能越过 Biz 归属检查。
- 无数据库策略仍只读；SQL 替换保持事务，不使用隐式建表、SDK AutoSave 或新增公开策略 API。

**关键失败路径**：合法新资源被误拒绝、未知资源/操作被接受、策略撤销后仍命中缓存、重复权限映射、加载或替换半途失败。

**验收与交付**：通过实际生成项目验证启动/离线目录一致、允许/拒绝/无角色、主体与角色混淆、失败保留旧快照及取消；SQL 事务由真实数据库验收，Redis 交叉安全路径在 R10 重验。同步授权文档，独立 `feat:` 提交。

#### D6-R04：迁移版本、schema 核验与方言草稿

**目标与范围**：修改迁移和数据库模板的固定版本入口及资源迁移规划。当前 `base/migrations/migrations.go.tmpl` 只声明固定版本 1/2，不能承载新增资源迁移。

**施工项**：

- 实现 R01 确定的版本推导/校验接口，覆盖基础 schema、Casbin schema 和后续资源迁移；保持显式 migrate、启动只核验、不运行 AutoMigrate。
- `--migration` 只生成当前数据库方言草稿；从现有迁移确定下一版本，拒绝同号、非法命名和计划准备后的目录变化，不改写历史 SQL。
- 明确新资源表、保留字段、字段类型与约束的只读核验；未建表或 schema 不兼容时清楚报错，不能等首次业务请求才暴露内部 SQL。
- 不带 `--migration` 仍交付资源源码和人工 schema 指引，不能将「生成完成」等同「资源可运行」。

**关键失败路径**：迁移后版本超过旧固定值导致拒绝启动、版本重复/缺失、脏迁移、迁移事务失败、表缺失、字段不兼容、应用账号被要求具备建库权限。

**验收与交付**：文件 SQLite、隔离真实 MySQL/PostgreSQL 验证基础版本 → Casbin（按选择）→ 两个新增资源、重启核验与失败回滚；应用和测试账号分离，不重置已有数据库。草稿审核及 schema 失败测试通过后，以独立 `feat:` 提交并更新数据库契约。

#### D6-R05：字段映射与主体隔离 CRUD 核心

**目标与范围**：在资源模板中生成 `internal/apiserver/model/`、`biz/<name>/`、`store/<name>/` 及必要校验/转换和测试；保持直接实现，不新增通用 CRUD 基类或泛型仓储框架。

**施工项**：

- 映射 `string/bool/int64`、保留字段与时间；字符串按 Unicode 字符数限制，创建时 required 表示必须出现，空字符串、`false`、`0` 合法。
- PATCH 明确区分未提供和写零值，拒绝 null、未知字段、重复字段及空更新；协议适配负责输入存在性，Biz 复核领域有效性。
- owner 只从认证 Context 注入；列表、读取、更新、删除均在数据库查询条件中限定 owner，不信任客户端 owner，也不先读取跨主体数据再过滤。
- 实现创建、单项查询、分页列表、部分更新和删除；分页/排序/错误语义按 R01 定稿，Store 传递 Context，更新使用明确字段集合，禁止结构体零值被 ORM 静默忽略。
- 不把 `int64` 转成 float64；不复制认证、日志或数据库连接管理，不给无数据库项目生成假 Store。

**关键失败路径**：跨主体读写、零值更新被忽略、长 Unicode 文本误判、int64 边界精度损失、分页越界、记录不存在、取消/超时及 SQL 失败暴露内部错误。

**验收与交付**：三种真实数据库验证两主体完整 CRUD、边界/无效字段、零值 PATCH、持久化重启、取消和错误映射；必要竞争场景执行 race。生成源码可独立 readonly 编译测试，交付核心模板与测试，独立 `feat:` 提交。

#### D6-R06：HTTP 入口、OpenAPI 与模块文档

**目标与范围**：增加 HTTP 资源 Handler、工厂描述和模块 Swagger 2.0 源，接入既有 HTTP 登记与 OpenAPI 合并；只生成新资源的业务文件。

**施工项**：

- 实现 `/v1/<name>`、`/v1/<name>/{id}` 的 CRUD 与操作权限；复用 JWT、Casbin、请求 ID、错误响应、预算、日志和输入限制。
- 实现严格 JSON 与路径/query 校验，owner 和保留字段不可写；验证 ID、分页、类型、未知/重复键、null 和零值，文档与实际响应保持一致。
- 新工厂显式构造 Store → Biz → Handler，使用应用已有数据库，操作描述精确登记；不修改旧工厂或静态 providers。
- 生成对应文档、可运行调用示例和有意义的测试，合并 Swagger 前检查路径/operationId/定义冲突，不重新生成旧模块文档源。

**关键失败路径**：路由未登记或误开放、未认证/无权限/外主体请求成功、文档显示字段与实际输入不同、第二资源加入后丢失旧路由或手工接线。

**验收与交付**：文件 SQLite 实际进程验证两个资源、两主体、JWT/Casbin 和输入边界，增加第二资源后旧模块仍可调用、原字节保持。纯 HTTP 不带 RPC 依赖，readonly test/vet/lint 通过后独立 `feat:` 提交。

#### D6-R07：gRPC、dual 与多模块协议复现

**目标与范围**：增加资源 Proto、RPC Handler、工厂权限映射，以及升级 gRPC/dual 的项目内协议脚本。当前 `variants/grpc/common/scripts/proto.py.tmpl` 只处理内置模块，需要支持多模块。

**施工项**：

- 为新模块生成独立 Proto 和公开 Go 协议类型，使用存在性字段表达创建/PATCH；保持 int64 精度、校验和错误映射契约。
- 每个 RPC 登记精确 FullMethod → 资源/操作，不增加未经认证授权的业务流；同一输入经 HTTP/RPC 得到一致 Biz 结果。
- dual 同一工厂只构造一次 Biz，HTTP 和 RPC 可互相读取/修改数据；保留现有双监听、就绪、失败清理和并发排空行为。
- 显式协议复现能发现多个模块，检查固定 protoc/plugin 版本及导入冲突；临时生成成功并确认范围后再更新对应协议产物，不修改业务源码、工厂、spec 或迁移。
- 新资源命令只编译新资源协议；普通构建不执行 protoc、不安装工具、不依赖 goseed 运行时。

**关键失败路径**：工具缺失/错版、编译错误、同名 Proto 导入、方法未登记或权限绑错资源、PATCH 存在性丢失、重复 Service、跨协议授权差异、取消不下传。

**验收与交付**：实际 TLS RPC、两资源/两主体 CRUD、边界/取消、独立客户端导入、dual 同一 Biz 与跨协议交叉调用；含内置模块与两个新资源的协议产物逐字节复现。同步协议文档，按可独立验收功能分别 `feat:` 提交。

#### D6-R08：Gateway 映射与汇总文档复现

**目标与范围**：增加资源 `http.yaml`/文档描述及 Gateway 工厂登记，升级 Gateway 协议生成脚本和聚合复现路径；复用 RPC Biz，不生成重复 Gin 业务 Handler。

**施工项**：

- 明确集合/单项路径、允许的 query 参数、JSON body 方法与 RPC 映射；继续由模块描述驱动输入检查、路由日志和请求限制。
- 验证 Authorization、请求 ID、预算/取消通过实际 Gateway → RPC 链；严格遵循 JWT → Casbin → Biz/缓存，不在 HTTP 层另写一份授权逻辑。
- 对齐 ProtoJSON 的 int64 表达和字段存在性，示例明确协议差异，校验零值、null、未知/重复键及非法 query。
- 显式协议复现维护当前模块的受声明生成文档，再确定性合并所有模块源与更新汇总摘要；不能用单份内置 Swagger 覆盖聚合索引。手工源保护和冲突行为按 R01 定稿。

**关键失败路径**：生成新模块后旧 HTTP 映射消失、协议复现丢失旧 Swagger 路径、汇总与摘要不一致、权限绕过、错误映射或 ProtoJSON 精度不一致。

**验收与交付**：真实 Gateway HTTP 与直连 RPC 对照两主体 CRUD，增加第二资源后路由/文档均保留，完整协议/文档复现一致；保持先 HTTP 后 RPC 排空。readonly 检查与代表进程验收通过后独立 `feat:` 提交。
