# 产品需求

## 目标与使用场景

为中小型 Go 后端业务提供一套结构稳定、易于理解的生产基础项目，减少重复搭建配置、日志、协议入口、数据库、鉴权与工程工具的工作。

核心场景包括：从空目录创建业务项目；按需求选择数据库、缓存、授权和协议；为现有生成项目新增业务模块；根据结构化字段声明生成简单 CRUD。

生成结果为普通 Go 项目，拥有完整源码，可以独立演进、测试和部署。生成器不成为业务项目的运行时框架，不接管业务逻辑。

## 已确定的默认行为

- 无参数执行 `goseed`，在当前符合生成条件的目录创建项目。
- 默认协议为 Gin HTTP，数据库为文件 SQLite，默认提供 JWT 认证能力。
- 使用 Handler → Biz → Store 分层，并生成一个端到端的 `example` CRUD 业务模块。
- 项目名默认取目录名，合法名称规则及 Go 模块路径规则见命令契约。
- 默认具备配置、日志、参数校验、业务错误映射、请求 ID、迁移、健康检查和优雅关闭。
- 生成文档、必要测试、Makefile、Dockerfile 和按需选择的本地 Compose 配置。
- 无必填交互问答；选择能力通过参数完成。
- 一键生成不包含自动安装全局工具、自动启动容器、自动应用迁移或自动公开发布。

## 首版可选能力

| 维度 | 支持范围 | 默认值 |
|---|---|---|
| 数据库 | SQLite、MySQL、PostgreSQL、无数据库 | SQLite |
| 认证 | JWT（固定基础能力） | JWT |
| 授权 | Casbin RBAC、无通用授权组件 | 无通用授权组件 |
| 缓存 | Redis、无缓存 | 无缓存 |
| 协议 | HTTP、gRPC、HTTP/gRPC 双入口、gRPC-Gateway | HTTP |

所有选项都属于首版交付范围，按依赖顺序分检查点实现。完整参数、依赖约束与非法组合以 `cli.md` 为唯一命令契约。

## 功能需求

### 项目生成

生成源码、匹配的依赖、配置模板、文档、测试和构建部署文件。JWT 是固定基础能力；未选择的数据库、授权、缓存与协议能力不引入对应运行依赖、不增加配置要求。

生成结果记录模板版本、模块路径、选定能力和模块登记，供业务生成器使用；运行服务不读取这份生成器元数据。

写入前完成名称、模块路径、目标目录、符号链接、能力组合、模板渲染与文件冲突检查。生成失败必须明确指出原因和是否有已写入文件；不得覆盖用户已有文件。

### 业务生成

- `gen module` 生成适合复杂业务的协议入口、Biz 以及按数据库能力选择的仓储接口与实现骨架。
- `gen resource <name> --spec specs/<name>.yaml` 从版本 1 YAML 字段声明生成简单 CRUD、模型、DTO、基础校验、转换、仓储、协议入口、注册、接口文档和必要测试；字段格式与边界以 [命令契约](cli.md#生成-crud-资源) 为准。
- 根据协议模式生成 HTTP、gRPC 或 Gateway 入口，所有入口共享同一业务实现。
- 支持 dry-run，在不写入的情况下展示计划、冲突和依赖要求。
- 自动登记模块和入口；拒绝重复模块名、非法字段、保留标识符、路径越界和重复注册。
- `goseed.yaml` 维护模块清单；`modules_gen.go` 由清单确定性生成，并校验清单摘要及生成标记。业务源码生成一次后由开发者维护；新增模块时仅更新这两个登记文件，以及 HTTP、dual、Gateway 的 `api/openapi/swagger.json` 汇总索引，发现人工修改则失败。纯 gRPC 不生成 HTTP OpenAPI 文件；文件归属及摘要规则以 [命令契约](cli.md#业务生成登记与文件归属) 为准。
- 数据库迁移通过显式选项生成草稿，供审阅；生成命令不连接数据库或执行迁移。
- 不推断订单、支付、库存等复杂业务规则。

### 数据库

SQLite 使用文件持久化，适配单机部署；MySQL、PostgreSQL 使用对应官方 GORM 驱动和适合各自的连接配置。

按所选数据库生成迁移与集成测试。处理字段类型、主键、时间、索引、唯一约束和错误映射差异；不得以 SQLite 测试结果代替其他数据库验证。

取消数据库时移除 ORM、驱动、数据库迁移和持久化示例，改为不需要存储的业务示例。不得自动改用内存 Store。数据库切换与已有数据转换不属于项目生成命令。

### 认证与授权

JWT 默认提供签发与验证组件、身份上下文及协议入口认证。示例业务默认受保护，公开入口显式登记；模板不包含通用默认密钥或默认管理员密码。

Casbin 通过参数增加，使用稳定的资源与操作名称实现 RBAC。HTTP 路由与 gRPC 方法映射到同一权限语义，策略默认拒绝。身份认证、通用授权、业务资源归属分别负责，不互相替代。

Casbin 策略按所选数据库持久化；无数据库模式使用只读文件策略。首版面向单实例，不包含跨实例策略同步或公开策略管理 API。

完整账号系统，包括注册、登录、密码找回、刷新 Token、会话撤销，不属于默认模板；后续可作为独立业务模板设计。默认开发路径必须能通过明确的本地开发工具获得测试 Token，不能靠公开无验证的签发接口。

### Redis

按参数提供客户端、配置、超时、关闭管理、健康检查及缓存示例。缓存约定覆盖 Key 命名、TTL、命中、回源和写入后失效。

可选缓存故障允许回源；业务将 Redis 用作必需状态时，需显式指定依赖要求与故障行为。开启 Redis 不自动改变 JWT 会话或 Casbin 策略存储。

首版 Redis 不附带消息队列、分布式锁或限流系统。

### 协议

HTTP 默认使用 JSON；gRPC 提供 Proto、注册、拦截器、标准健康检查和示例客户端；Gateway 根据 Proto HTTP 映射提供 JSON 入口。

默认业务生成以 unary RPC 为范围。首版不生成流式业务；如后续开放流式方法，必须同步提供 stream 认证、授权、恢复和测试，不能直接暴露缺少拦截器的流式入口。

跨协议共享输入校验和业务语义，分别输出正确的 HTTP 状态或 gRPC Status。请求 ID、认证信息、截止时间和取消状态需要贯穿调用链。

### 工程与运维

配置强类型解析并在启动前校验；生产日志输出结构化 JSON；敏感配置与数据库内容不默认进入日志。具备存活和就绪检查、启动失败清理和有期限的关闭流程。

提供 HTTP/gRPC TLS 配置能力，证书必须正确校验；pprof、Reflection 等调试入口生产默认关闭。CORS 使用显式允许来源，缓存头按接口需要设置。

部署默认围绕单实例应用：SQLite 持久化目录；MySQL、PostgreSQL、Redis 按能力生成开发 Compose 服务。Kubernetes、systemd、Nginx 作为后续独立部署模板，不默认注入主项目。

指标、链路追踪、任务系统及消息队列属于后续扩展，不纳入本版运行链。

## 非功能要求

- 简单直接：标准库优先，不为每层增加重复类型或无用途接口。
- 可维护：依赖仅在清晰边界使用；业务不使用容器定位服务。
- 可复现：模板与依赖版本固定；生成结果可重复编译和验证。
- 安全：无隐式覆盖、默认弱密钥、鉴权绕过或生产自动迁移。
- 可诊断：失败说明包含具体对象与原因，不泄露密钥、DSN 或数据库内部错误。
- 可演进：模板升级不自动重写既有项目，数据库方言差异不隐藏为完全兼容。

## 源码与文档交付

仓库以独立项目方式维护产品需求、架构、技术方案、CLI 契约、完整施工清单和源码导航。规范文件使用仓库相对链接，不依赖某台电脑的目录或聊天记录。当前状态只维护在 ROADMAP；目标需求不能冒充已经实现的能力。

新开发环境能够从 Git 源码和固定版本清单恢复构建、协议工具及验证入口；业务运行不得依赖 `.tmp/`、`.tools/` 或开发者本地配置。真实配置、凭据和数据库不属于公开源码交付物。

项目使用 MIT 许可证，第三方依赖及生成代码的版权/许可说明保留。源码公开与首版功能完成是不同状态，发布说明应明确已交付能力和验证边界。

## 验收标准

1. 空目录无参数生成后，项目可编译、通过基础测试，并在不部署数据库服务的情况下完成 SQLite CRUD 和 JWT 保护入口调用。
2. MySQL、PostgreSQL 分别通过真实数据库的建库迁移、CRUD、唯一约束、分页和事务回滚测试。
3. 无数据库项目不含 ORM 与数据库配置要求，服务和非持久化示例可运行。
4. HTTP、gRPC、dual、gateway 四种模式分别可运行；双入口与 Gateway 的身份、错误及业务结果一致。
5. Casbin 在支持的存储模式中通过允许与拒绝测试；未认证与权限不足得到不同且正确的响应。
6. Redis 缓存命中、失效、回源及必需依赖失败行为可验证。
7. 配置非法、必需依赖失败、启动中途失败、请求取消与关闭超时均有验证；资源不会因失败路径遗留。
8. 业务生成完成后可编译、调用和测试；冲突、重复生成、非法字段、越界路径与 dry-run 不造成用户文件改写。
9. 生产可用声明以已完成的验收范围为依据；具体业务的容量、授权规则、备份恢复与上线评估仍需实际项目验证。
